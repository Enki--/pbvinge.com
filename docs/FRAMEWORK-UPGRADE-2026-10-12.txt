COMPATIBILITY CHANGES

Content Layer schemas/loaders now live in src/content.config.ts. Explicit file
loaders retain raw note bodies, exclude underscore-prefixed content paths, and
keep the previous nested URLs through legacyContentId. Consumers use entry.id
and render(entry). The supported unified Markdown processor preserves the
existing pipeline, with compressHTML:true retaining HTML-aware inline spaces.

The current Markdown heading collector no longer removes one trailing hyphen.
Whole-output comparison caught 50 changed existing heading URLs on seven notes.
A bounded rehype plugin reuses the current exported collector and restores the
old suffix handling only for generated IDs. Explicit author IDs and duplicate
ordering remain intact. The built-in collector then generates matching TOC data.

Tailwind now uses its supported Vite plugin, with explicit src-only scanning.
Compatibility CSS preserves the used v3 palette, border/placeholder defaults,
button cursors, select text transform and search appearance. Cover shadow-sm
became its equivalent shadow-xs. The planning inputs/selects explicitly retain
native system Field backgrounds after baseline browser inspection by root.
Custom application CSS stays unlayered. No archive content is scanned for CSS.

Book Added/Updated labels now use UTC calendar formatting. This repairs the
verified Mini/Cloudflare date drift without changing stored timestamps or their
sorting. Equal created/updated instants no longer print a redundant Updated
label. The checker wrapper resolves Astro's published CLI bin instead of the
removed astro.js filename. Active development guidance reflects these changes.
